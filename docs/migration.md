# 从 rsr 提取 stub

本模板从原 `rsr` 多任务项目提取通用骨架，目标是为新项目提供结构参考和可运行的最小通路。原项目保持原样，迁移采用提取副本的方式，不删除其代码、资产、配置和历史结果。

## 保留范围

| 来源 | 模板内容 |
|---|---|
| `real2sim2real/core/` | 配置加载、Pydantic 基类、Registry、CLI、日志 |
| 五个能力域的 `base.py` | 组件基类、工厂、Job 生命周期与钩子 |
| 五个 stub 后端 | 最小配置类与实现类 |
| Job CLI | `collect run` 入口 |
| 包和 entry points 协议 | 保留 `real2sim2real` 导入和插件组名，注册项收敛为 stub |
| 结构约定 | 按任务组织代码、配置、脚本、资产、文档与输出 |

源仓库提取时的 HEAD 为 `2007c572599bd291492f4eed6a448a2f3897981f`。提取以当时工作目录中的实际文件为准，可能包含尚未提交的修改，因此该提交号用于定位背景，不保证与迁入文件逐字一致。

## 清理与补充

- 发行包使用 `rsr-stub`，删除旧业务后端注册和任务专属可选依赖；默认环境只安装骨架实际使用的依赖。
- 默认配置只描述 stub，移除旧任务的注释参数、资产路径、渲染和采集设置。
- README、AGENTS 和环境说明围绕模板重写，提供创建新项目的完整扩展例子。
- 提供普通 Python 开发通路、可提交的依赖锁文件和通用运行包装；真实仿真运行时由后续项目单独接入。
- 补齐 Scene / Robot 的 `adjust()` 接口与 Job 默认调用，使代码与生命周期说明一致。
- 统一 stub Planner 的机器人引用和就绪状态，避免初始化后状态与实际装配不一致。
- 保留基础回归验证，覆盖配置、插件发现和生命周期，避免把旧任务测试误当成模板验收。
- 简化环境忽略规则和编辑器配置，避免继承旧机器安装路径及失效的业务启动参数。

## 未提取的内容

旧项目的物理求解器、分拣、巡检、HALO、电池拆解、桌面抓放与回放等业务实现、配置、资产和结果不属于骨架。Isaac Sim 实现及相机、数据集导出等重型辅助也不随 stub 搬入；新项目需要时按依赖关系单独迁移并验收。

原项目 `.agents/skills/` 中的任务开发、物理调试和调参说明包含具体业务、运行时和资产背景，没有整包复制。后续项目如需使用，应先核对当前目录、实现和运行时，再提取适用部分。

原项目文档用于理解既有结构，不能替代新项目的需求和验收标准。旧项目“必须使用某机器环境”“运行某业务任务”等说明，也不自动适用于这个纯 stub 模板。

## 后续迁移任务时

按 [创建新项目](new_project.md) 的目录与注册流程迁移单个任务，逐项核对导入、配置类、entry points、资产依赖和真实运行时。先证明最小通路，再执行任务自己的物理或数据验收，并在任务文档中记录验证范围。
